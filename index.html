Ownership

Buy the machines once. Run SI without a bill.

Both Danav Server and Danav are self-hostable. The models run on your own server, so intelligence does not depend on a subscription or on an AI company's API.

Danav Server

The SI runtime and management platform. It needs the RAM and resources of its machine, so give it the strongest system you have.

  • Install any open-source model and tune how it runs for the intended work, for faster results.
  • Route each request by intent, complexity, capabilities, latency and available resources.
  • Issue individually generated API keys with scoped permissions.
  • Support multiple users, clients, endpoints and access permissions.
  • Run on the same machine as Danav, or on a separate local or remote server.
  • Manage model availability, resource allocation, task execution, logs and usage.

Danav

The lightweight client. It connects to a Danav Server with an API key and does the work you ask for.

  • Add an SI harness and create multiple agents for your different kinds of work.
  • Handle conversation, coding projects, command-line operations and autonomous task workflows.
  • Turn requests into structured tasks and make type-safe tool calls with validated inputs and outputs.
  • Execute tasks, inspect results, run tests and recover from failures.
  • Connect to any Danav Server with its endpoint and an API key from that server.

Danav Router

Six decisions before any text is generated

Danav carries its own lightweight intent model. It uses the smallest model that can do the job, favors the fastest suitable path, avoids unnecessary reasoning and repeated text, and escalates to a more capable model only when the work requires it. Which levels exist depends on the models installed on your server.

  1. 1

    Intent

    What does the person want?

    Reads the request and works out which capabilities it needs.

  2. 2

    Route type

    Model, tool, operation or a mix?

    Some work needs no model at all. A deterministic operation is faster and always gives the same answer.

  3. 3

    Model

    Which installed model fits?

    Chooses among the models on the server by capability, latency and available resources.

  4. 4

    Budget

    How small can the model be?

    Picks the smallest suitable model and an appropriate compute budget for the task.

  5. 5

    Action

    Execute, plan, delegate or ask?

    Runs the task directly, writes a plan, hands subtasks to other models, or asks the person for clarification.

  6. 6

    Verdict

    Is the result right?

    Checks the output and decides whether more work is needed. If it is, the task moves up to a more capable model.

Principles

Seven principles behind every design choice

Local-first
Run models on hardware you control, with no mandatory paid AI APIs.
Model-agnostic
Install any open-source model, across different model families and inference runtimes.
Efficiency-first
Optimize response time, memory use and compute cost.
Type-safe execution
Use structured schemas, validated tool calls, explicit error handling and predictable interfaces.
Task-oriented
Finish and verify the work instead of only generating text.
Extensible
Add new models, tools, runtimes and capabilities independently of each other.
Secure by design
Authenticate clients, scope API keys, enforce permissions and isolate potentially dangerous operations.

The idea

Danav decides how much intelligence a task needs, then uses the right model at the right time.

The server carries the models and the compute. The client stays light and does the work. You own both systems, with no subscription and no AI company in the loop.
