Problem statement

Four systemic failures across fragmented AI silos

Modern developers and power users operate across fragmented AI silos—Claude Code in one terminal, Cursor in an IDE, Gemini CLI in another tab, Codex for background tasks, and local models via Ollama. Every tool suffers from four systemic failures:

Context Amnesia & Siloing
Architectural decisions, bug fixes, and user preferences learned in one tool are invisible to the others.
Token & Latency Bloat
Agents repeatedly read 1,500-line files from scratch instead of surgical AST symbol slices, wasting context windows and money.
Generative Routing Waste
Slow, expensive frontier models are used for trivial classification, routing, and safety checks that should take less than 20ms.
Subscription Lock-In
Users pay for multiple AI subscriptions and API quotas but lack a single unified workspace to pool those subscriptions and run custom cross-app agents on their own hardware.

Vision and personas

One brain, every model, owned by you

Core value proposition

  • One Brain, Every Model: Every CLI, IDE, and agent reads from and writes to a single local relational memory graph and AST index.
  • Zero-Search Surgical Context: Turn-1 prompts automatically receive a sub-15ms, 400–600 token context_pack containing exact AST symbol line ranges, relevant relational memories, and active test states—cutting token consumption by up to 80%.
  • Sub-50ms TypeSafe System One Routing: Every internal decision (routing, tool selection, safety gating, memory promotion) uses constrained zero-text primitives (Choice, Score, Noul) with a 0% structural hallucination guarantee.
  • Bring Your Own Subscription (BYOS) Agent OS: The Danav Desktop App turns passive AI subscriptions and local models into proactive, cross-app workers governed by strict local privacy and resource caps.

Target personas

  • Persona A — The Polyglot AI Engineer (Danav Brain CLI): Uses multiple coding agents daily; wants instant context sharing across tools, lower API bills, zero-latency AST slicing, and 100% local data ownership.
  • Persona B — The Autonomous Power User / Builder (Danav Desktop App): Wants to build custom background agents that connect GitHub, Notion, Gmail, Slack, Browser, and local files using their existing AI plans without paying a SaaS middleman.
  • Persona C — Privacy-Conscious Engineering Teams: Needs peer-to-peer memory and skill syncing across a local network with strict secret redaction and zero cloud lock-in.

TypeSafe System One

Zero-text decisions before any model writes a word

Every internal judgment (routing, tool selection, safety gating, memory promotion) is a schema-locked Choice, Score or Noul that outputs numbers only. Anything below the confidence bar escalates to System Two.

Instead of prompting a generative LLM with “Please respond in JSON,” danav-system1 intercepts state and evaluates constrained primitives in a single forward pass using logit masking over a local quantized model (e.g., Qwen-2.5-0.5B/1.5B-Instruct or a fine-tuned ModernBERT classifier via ONNX):

  1. Choice(options: &[&str]) ->ChoiceResult:
    • Masks the vocabulary softmax layer exclusively to the token sequences representing options[0..N].
    • Computes exact normalized sequence probabilities:
    P(oi | S) = exp(logit(oi))Σj=1N exp(logit(oj))
    • If maxi P(oi | S) < τchoice (pinned in danav-decisions.lock, default 0.80), triggers automatic System Two escalation (#30).
  2. Score(rubric: &Rubric) -> f32:
    • Masks logits to integer tokens [1..K] corresponding to explicit literal criteria definitions.
    • Computes the expected continuous score via probability-weighted interpolation:
    Score(S) = Σk=1K k · P(k | S)
  3. Noul(predicate: &str) -> f32:
    • Evaluates a strict boolean invariant by masking output exclusively to {Yes, No} tokens:
    P(Yes | S) = exp(logit(Yes))exp(logit(Yes)) + exp(logit(No))

Context pack pipeline

A 15 ms budget on every Turn 1

When a prompt is sent from Claude Code, Cursor or the Danav App, danav-proxy or danav-mcp assembles the surgical context under a strict 15 ms wall-clock budget.

  1. 1

    0–2ms

    Deterministic Pre-Compute

    Reads dirty git status, active terminal stack trace (#41), and open file cursors from the in-memory watcher.
  2. 2

    2–7ms

    Parallel Hybrid Recall + AST Lookup

    • Runs FTS5 BM25 + quantized sqlite-vec search across active memories (status = 'active').
    • Traverses 1-hop UPDATES/EXTENDS edges and memory_symbol_anchors to pull linked AST symbols.
    • Queries ast_symbols for compressed skeletons (read_skeleton) of co-edited files (#40).
  3. 3

    7–12ms

    System One Filtering & Compaction

    Runs a parallel Noul relevance pass and strips any secret/PII strings (#62).
  4. 4

    12–15ms

    Prefix-Aligned Injection

    Formats the deterministic 400–600 token XML/Markdown <danav_context_pack> block and appends it after the static cached system prefix (#9).

IIITypeSafe System One Decision Engine10
026System One vs. System Two Split Architecture
Never wastes a slow generative LLM call on routing, classification, relevance filtering, or safety checks; runs a sub-50ms TypeSafe Decision Layer in front of every generative model.
027Zero-Text Constrained Decision Primitives (Choice, Score, Noul)
Every internal brain judgment is framed as one of three strict, schema-locked question types that output numbers/enums only—never free-form text:
  • Choice(options[1..255]): Picks from an enumerated list and returns a probability distribution plus confidence score.
  • Score(rubric[2..10]): Evaluates state on an ordered 2–10 level rubric with continuous interpolation.
  • Noul (Binary 0.0–1.0 Probability): Answers a strict Yes/No predicate as a single probability value.
028Single-Pass Parallel Question Evaluation
Evaluates multiple Choice, Score, and Noul questions against a piece of state in a single parallel forward pass (routing + tool selection + risk check + memory promotion).
0290% Structural Hallucination Guarantee
Constrained decoding and logit-level token masking make off-schema strings, invalid tool names, or fabricated file paths structurally impossible.
030Confidence-Threshold Gating & Escalation
Every Choice and Noul decision checks a tuned probability bar (e.g., p ≥ 0.80); anything below automatically escalates to a System Two reasoning model.
031Pre-Decision State Compaction
Automatically strips unrelated conversation history and noise before passing state to the TypeSafe decision layer so irrelevant context never degrades classification accuracy.
032Deterministic Pre-Compute for Math, Counts & Dates
Computes line counts, timestamps, token budgets, and file sizes deterministically in native Rust code first, then feeds exact values into the TypeSafe decision layer.
033Literal Criteria & Structural Invariant Enforcement

034Pinned Decision Rubrics & Version Locking

035Loose-Text-to-Schema Extractor

108Human-in-the-Loop Escalation Inbox (Async Approval Queue)
When a background agent hits a low-confidence System One gate (p < 0.80) or a high-risk policy boundary while working across apps, it pauses state and pushes a 1-click “Approve / Modify / Reject” card to the Danav App UI and mobile notification channel.
109Cross-App Data Lineage & Taint Tracking
Tags data pulled from untrusted external apps (e.g., an incoming email or public web page) as tainted, preventing any downstream agent from passing that payload into a shell command or private database query.
110Portable Agent Blueprints (.danav-agent Manifests)
Packages an agent’s persona, System One decision rubrics, required app connectors, and distilled skills into a single shareable file so users can install or share community-built agents in one click.

Danav Application technical requirements

Tauri v2, React and a Rust core

One frontend serves both the localhost:7420 dashboard and the native desktop app.

4.1 Application Architecture (Tauri v2 + React + Rust Core)

Rather than building two separate codebases for the local web dashboard (localhost:7420) and the standalone Danav Desktop Application, both are built from a single apps/danav-desktop frontend wrapped with Tauri v2:

  • Headless Server Mode (danav ui): danavd serves the compiled static frontend bundle directly on http://127.0.0.1:7420 over WebSockets/REST.
  • Native Desktop Mode (Danav.app / Danav.exe): Tauri embeds danav-daemon directly into the native OS binary, communicating via zero-copy Tauri IPC commands and managing system tray hooks, global OS shortcuts, and accessibility permissions.

4.2 Unified BYO-Subscription & Compute Pool Engine (#103)

Users should never have to pay Danav a markup on tokens when they already pay for AI tools. Danav Desktop implements three compliant adapter lanes inside the Unified Compute Pool:

  1. Official CLI Session Lane (Zero API Cost): Spawns and pools persistent headless sessions of installed official CLIs (claude, gemini, codex) inside managed PTYs (portable-pty), routing agent subtasks through the user’s existing CLI plans while respecting rate limits.
  2. Direct API Key Lane (BYOK): Connects directly to Anthropic, OpenAI, Google Gemini, Groq, and OpenRouter keys stored in the OS Keychain (#63), applying automatic prefix caching (#9) and budget ceilings (#83).
  3. Local Inference Lane (Zero Cloud Cost): Auto-discovers local Ollama, LM Studio, vLLM, and embedded llama.cpp endpoints for offline coding, privacy-restricted folders (#94), and background Sweeper tasks (#74).

4.3 Deterministic DAG Workflow Compiler (#107)

When a user creates an agent in Danav (e.g., “Every morning at 9 AM, check my GitHub PR reviews, cross-reference failing CI logs with our local codebase, draft a fix in an ephemeral worktree, and ping me on Slack with an approval card”):

  1. Compile

    Compilation Step

    A System Two model translates the natural language prompt into a typed workflow.danav.json Directed Acyclic Graph (DAG).

  2. Execute

    Execution Step

    Every node transition in the DAG is governed by a deterministic Rust tool call or a sub-50ms System One Choice/Noul gate. Generative LLMs are invoked only at nodes that require synthesis or code generation.

  3. Enforce

    Taint Enforcement (#109)

    Every edge in the DAG carries a SecurityLabel { integrity: Trusted | Untrusted, confidentiality: Public | Private }. If a node ingests an external email or web page (Untrusted), the Policy Engine (#60) blocks any downstream node in that execution trace from invoking run_shell, edit_symbol, or outbound network POSTs unless the user clicks Approve in the Escalation Inbox (#108).

4.4 Universal App-State Graph: OS & Browser Automation (#57, #105)

To let Danav agents interact with any desktop application (Slack, Figma, Linear, ERP dashboards, Excel) without burning thousands of vision tokens on screenshots:

  • macOS (AXUIElement) / Windows (UIAutomation) / Linux (AT-SPI2): A native Rust OS bridge queries the active window’s accessibility tree and serializes interactive elements (buttons, text fields, tables, menus) into a compact, numbered Markdown/DOM snapshot (<button id="@e14">Submit</button>).
  • Playwright / CDP Bridge: Attaches to an isolated browser profile (#58) and extracts the accessibility tree. Vision models are called only when a System One Noul("contains_canvas_or_chart") check returns p ≥ 0.80.
